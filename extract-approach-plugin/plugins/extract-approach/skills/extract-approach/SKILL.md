---
name: extract-approach
description: after solving any non-trivial problem, document the approach so a less capable model can replicate the thinking. triggers after debugging, architecture decisions, tricky builds, or any solution that took real reasoning
---

after solving a hard problem, write one note to learnings/<date>-<slug>.md:

> the problem, in one line
> the approach: how the problem was decomposed, in plain steps
> the judgment calls: what was deliberately NOT done, and why
> the reusable rule: the one-line principle a future model should apply when it smells a similar problem

keep it under a page
write it so a weaker model reading it cold could follow the same path
