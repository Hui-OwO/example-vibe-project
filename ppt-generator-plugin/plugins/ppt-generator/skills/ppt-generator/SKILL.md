# PPT 발표자료 생성

이 스킬의 목표는 "빈 화면 앞에서 막막한" 단계를 없애는 것이다. 좋은 발표 자료는
슬라이드를 예쁘게 그리는 것보다 **누구에게 / 얼마의 시간 동안 / 무엇을 남길지**가
먼저 정해져야 나온다. 그래서 곧장 슬라이드를 찍어내지 말고, 아래 순서대로 청중과
메시지를 먼저 잡은 다음 내용을 채우고, 마지막에 번들 스크립트로 .pptx를 출력한다.

`.pptx` 변환은 `scripts/build_pptx.py`가 결정적으로 처리하므로, 당신은 **레이아웃이
아니라 내용**에 집중하면 된다.

---

## 1. 먼저 4가지를 확인한다 (건너뛰지 말 것)

슬라이드 구성과 톤은 이 4가지에 따라 완전히 달라진다. 사용자가 처음 요청에서 이미
일부를 줬다면 그건 그대로 쓰고, **빠진 것만** 한 번에 모아서 물어본다. 전부 다시
묻지 말 것.

| 항목            | 왜 필요한가                                                                 |
| --------------- | --------------------------------------------------------------------------- |
| **주제 / 목적** | 무엇을 다루는 발표인가. 정보 전달인가 설득인가 보고인가.                    |
| **대상 청중**   | 전문성 수준에 따라 용어와 깊이가 달라진다 (임원 vs 엔지니어 vs 일반).       |
| **발표 시간**   | 시간이 슬라이드 수를 정한다. **대략 1장당 1~2분** → 10분이면 6~10장 내외.   |
| **원하는 톤**   | 격식 있는 보고 / 캐주얼한 데모 / 설득적 피치 등. 문장 길이와 어휘가 바뀐다. |

> 사용자가 "알아서 해줘"라고 하면, 합리적인 기본값(중간 톤, 일반적 청중, 10분, 8장
> 내외)을 **제안하고 동의를 받은 뒤** 진행한다. 멋대로 가정하고 끝까지 가지 말 것.

---

## 2. 목차와 슬라이드 구성을 먼저 설계한다

내용을 다 쓰기 전에 **뼈대부터 사용자에게 보여주고 합의한다.** 여기서 방향이 틀리면
뒤의 작업이 통째로 낭비되기 때문이다. 다음 형식으로 간단히 제시한다:

```
표지 → [도입] → [본문 섹션들] → [정리/Call to Action]

1. (표지) 제목 / 발표자
2. 왜 지금 이 주제인가 — 도입·문제 제기
3. 핵심 개념 A
4. 핵심 개념 B
...
N. 정리 & 다음 단계
```

좋은 발표의 흐름은 보통 **도입(왜 들어야 하나) → 전개(핵심 2~4개) → 마무리(무엇을
하면 되나)**다. 시간 대비 장수가 맞는지 꼭 점검하고, 사용자에게 "이 구성으로
진행할까요?"라고 확인한 뒤 다음 단계로 넘어간다.

---

## 3. 슬라이드별 내용을 작성한다

합의된 목차에 따라 각 슬라이드를 채운다. 슬라이드 하나는 **4가지 요소**로 구성한다:

- **제목(title)** — 짧고 명확하게. 가능하면 명사 나열이 아니라 메시지가 드러나게.
- **핵심 메시지(key_message)** — 이 슬라이드가 청중에게 남길 _한 문장_. 슬라이드
  상단에 굵게 들어간다. (없는 슬라이드도 있을 수 있다.)
- **본문(bullets)** — 핵심 메시지를 뒷받침하는 항목. **한 슬라이드에 3~5개**,
  한 줄은 짧게. 문장을 통째로 넣지 말고 키워드 중심으로. 하위 항목이 필요하면
  중첩 리스트로 표현한다.
- **발표자 노트(notes)** — 슬라이드에는 안 보이지만 발표자가 말할 내용. 슬라이드
  본문을 그대로 읽지 말고, **부연 설명·전환 멘트·예시·예상 질문 대응**을 담는다.

> 원칙: 슬라이드는 "말의 요약"이고, 발표자 노트가 "실제 할 말"이다. 본문에 문장을
> 빽빽이 채우면 청중이 읽느라 발표를 안 듣는다. 글은 노트로 옮기자.

---

## 4. JSON으로 구조화하고 .pptx를 출력한다

작성한 내용을 아래 스키마의 JSON 파일로 저장한다. (예: `deck.json`)

```json
{
  "meta": {
    "title": "발표 제목",
    "subtitle": "부제 (선택)",
    "author": "발표자 (선택)",
    "audience": "대상 청중",
    "duration_min": 10,
    "tone": "톤"
  },
  "slides": [
    {
      "layout": "section",
      "title": "도입: 왜 지금인가",
      "key_message": "지금 이 문제를 풀지 않으면 비용이 계속 커진다",
      "notes": "청중의 공감을 먼저 끌어낸다. 최근 사례 하나로 시작."
    },
    {
      "layout": "content",
      "title": "현황의 3가지 문제",
      "key_message": "병목은 사람이 아니라 프로세스에 있다",
      "bullets": [
        "수작업 반복 → 실수 잦음",
        "병목 구간이 보이지 않음",
        ["측정 부재", "개선 효과를 증명할 수 없음"]
      ],
      "notes": "각 항목마다 30초씩. 두 번째 항목에서 데이터 화면 전환."
    }
  ]
}
```

`layout` 값: `title`(제목형) · `section`(섹션 구분) · `content`(제목+본문, 기본값)
· `closing`(마무리). 표지는 `meta`로 자동 생성되므로 `slides`에 따로 넣지 않는다.

그런 다음 번들 스크립트로 .pptx를 생성한다:

```bash
python "<이 스킬 경로>/scripts/build_pptx.py" deck.json -o "발표제목.pptx"
```

- Python이 `python`으로 안 되면 `python3`로 재시도한다.
- `python-pptx`가 없으면 스크립트가 알아서 설치를 시도한다. 설치가 막힌 환경이면
  사용자에게 `pip install python-pptx`를 안내한다.
- `-o`를 생략하면 제목 기반 파일명으로 현재 폴더에 저장된다.

마지막으로 **생성된 파일 경로와 슬라이드 수**를 사용자에게 알려준다.

## 5. 자체 검증 체크리스트

.pptx를 출력한 뒤, 아래를 **스스로 점검하고** 어긋난 항목이 있으면 고친 뒤 다시
생성한다. 사용자에게는 통과 여부를 간단히 요약해 보고한다.

- [ ] **시간-장수 정합성**: 슬라이드 수가 발표 시간에 맞나? (1장당 1~2분 기준)
- [ ] **흐름**: 도입 → 전개 → 마무리 구조가 있고, 마지막에 정리/다음 단계가 있나?
- [ ] **한 슬라이드 한 메시지**: 한 장에 주제가 2개 이상 섞여 있지 않나?
- [ ] **본문 분량**: 슬라이드당 bullet 3~5개, 한 줄이 너무 길지 않나? (문장 떡칠 X)
- [ ] **발표자 노트**: 모든 본문 슬라이드에 노트가 있고, 본문을 그대로 읽기만 하지
      않나?
- [ ] **청중 적합성**: 용어 난이도와 톤이 처음 확인한 청중에 맞나?
- [ ] **파일 생성 확인**: 스크립트가 `OK: ...`를 출력했고 .pptx가 실제로 존재하나?

## 빠른 예시 (입력 → 행동)

**입력:** "다음 주 팀 회의에서 쓸 코드 리뷰 문화 개선 발표자료 만들어줘"

**행동:**

1. 빠진 정보 확인 — 청중(팀원? 전사?), 시간, 톤을 한 번에 묻는다. (주제는 이미 있음)
2. 답변을 받아 목차 6~8장을 설계해 보여주고 합의.
3. 각 슬라이드의 제목·핵심 메시지·본문·노트를 작성.
4. `deck.json` 작성 → `build_pptx.py` 실행 → `코드리뷰-문화-개선.pptx` 생성.
5. 체크리스트로 자체 점검 후 "8장 생성 완료, 경로는 ..." 보고.
