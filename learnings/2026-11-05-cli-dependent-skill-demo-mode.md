# CLI 의존 스킬을 CLI 없는 환경에서 만들고 테스트하기

**문제(한 줄):** 캘린더·GitHub PR·main CI를 모아 신호등 우선순위로 브리핑하는 `daily-briefing` 스킬을 만들어야 하는데, 필수 CLI(`gh`, `gcalcli`)가 개발 머신에 설치돼 있지 않았다 — 그래도 만들 수 있고 _테스트까지_ 할 수 있어야 했다.

## 접근

1. 사용자 스펙의 5단계(병렬 수집 → PR 변경분 분석 → CI 실패 로그 → 신호등 분류 → 마크다운 출력)를 그대로 `scripts/`의 bash 스크립트로 1:1 매핑.
2. **컨텍스트 절약을 1급 설계 목표로**: 수집 스크립트는 원시 출력 대신 압축 JSON Lines/TSV만 반환하고, CI 로그는 `gh run view --log-failed | tail -200`으로 마지막 200줄만.
3. **CLI 부재 대응**: 모든 스크립트 맨 위에 `if [ "${BRIEFING_DEMO:-0}" = "1" ]` 분기를 넣어 `fixtures/`의 샘플 데이터를 `cat`. 실데이터 경로와 데모 경로의 *출력 포맷이 동일*해서 뒷단 로직은 둘을 구분하지 않는다.
4. fixtures를 "하나의 아침 스토리"로 설계해 5단계를 전부 자극: `CHANGES_REQUESTED` PR(🔴), 24h 지난 리뷰요청(🟡), draft PR(🟢), main CI fail(🔴) + 그 실패 로그.
5. 데모 모드로 전 스크립트 스모크 테스트 → 그 다음 skill-creator eval 루프의 평가 대상은 "데이터 수집 연결"이 아니라 **step2~5의 LLM 판단 로직**임을 분명히 함.

## 의도적으로 하지 않은 것 (judgment calls)

- **라이브 데이터로 평가 안 함** — 실제 캘린더/PR은 비결정적·사적이라 재현 불가. 데모 fixtures로 로직만 결정적으로 평가하는 게 eval에 적합.
- **`reviewDecision`을 수집 스크립트(gh search)에 안 넣음** — `gh search prs`가 해당 필드를 미지원할 수 있어, 상세가 필요한 top-5에서 `gh pr view`(pr-summary.sh)로만 가져옴. 수집은 가볍게, 상세는 필요할 때.
- **"미응답 리뷰 코멘트"를 리뷰 스레드 파싱으로 정밀 구현 안 함** — `CHANGES_REQUESTED` 휴리스틱으로 근사. 비용 대비 충분하고, 틀려도 브리핑 한 줄의 분류일 뿐.
- **설치 위치를 프로젝트가 아니라 개인 `~/.claude/skills`로** — 아침 브리핑은 특정 레포가 아니라 하루 전체를 가로지르는 도구라서.

## 재사용 규칙

외부 CLI/서비스에 의존하는 스킬은 **처음부터 `*_DEMO=1` fixture 분기**를 넣어라 — CLI가 없어도 핵심 로직을 결정적으로 테스트·시연할 수 있다. 그리고 수집 단계는 원시 출력이 아니라 **압축 포맷만** 반환해 컨텍스트를 아껴라(로그는 tail, diff는 집계 한 줄).
