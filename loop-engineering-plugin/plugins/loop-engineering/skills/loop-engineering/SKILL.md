# Loop Engineering

에이전트에 직접 프롬프트하는 대신, **에이전트를 굴리는 루프를 설계**한다.
루프 = 목표 계약(`LOOP.md`) + 디스크 메모리(`.loop/memory.md`) + 반복 프로토콜 + 독립 검증.

## 모드 판별 (자기 라우팅)

프로젝트 루트에 `LOOP.md`가 **없으면 → Init 모드**, **있으면 → Iterate 모드**.
사용자가 명시적으로 "다시 설계", "목표 바꿔줘"라고 하면 LOOP.md가 있어도 Init 모드로 재설계.

---

## Init 모드 — 루프 설치

1. **목표 인터뷰** (이미 대화에 답이 있으면 묻지 말 것):
   - 목표: 한 문장. "무엇이 존재하면 끝인가?"
   - 검증 명령: 기계로 판정 가능한 명령 (`npm test`, `curl ...`, 빌드 등). 없으면 먼저 만들게 한다 — **기계 검증 없는 루프는 루프가 아니다.**
   - 제약: 금지사항, 기술 스택, 건드리면 안 되는 것
2. **Rubric 작성**: 목표를 3~7개의 **기계 검증 가능한** 체크 항목으로 분해한다.
   나쁜 예: "UX가 좋다". 좋은 예: "`npm test` 전부 통과", "`GET /api/x`가 200 + JSON 스키마 일치".
3. **스캐폴딩**: 이 스킬 폴더의 `templates/LOOP.md`, `templates/memory.md`를 복사해
   프로젝트 루트에 `LOOP.md`, `.loop/memory.md`를 생성하고 플레이스홀더를 채운다.
4. **자동화 안내**를 출력하고 멈춘다 (바로 반복을 시작하지 않는다 — 사용자가 계약을 확인해야 함):
   - 수동 1회: `/loop-engineering 이어서`
   - 자동 반복: `/loop /loop-engineering 이어서` (self-pacing)
   - 위험한 변경 격리: worktree에서 실행 권장

## Iterate 모드 — 반복 프로토콜 (1회 = 아래 6단계)

### 1. Consult — 메모리 먼저

`LOOP.md`와 `.loop/memory.md`를 읽는다. **Rules 섹션이 최우선** — 과거에 증명된 규칙을
어기는 시도를 반복하지 마라. 같은 실패를 두 번 기록했다면 그 접근은 금지된 것이다.

### 2. Select — 한 번에 하나

미달성 rubric 항목 중 **하나만** 고른다. 의존성이 있으면 선행 항목부터.
모든 항목이 ✅면 → 6단계(종료)로.

### 3. Implement — 최소 변경

그 항목을 통과시키는 **가장 작은 변경**을 구현한다.
스키마 변경·대규모 리팩터링 등 위험한 변경은 worktree(`isolation: worktree`)에서.

### 4. Verify — 작성자 ≠ 검증자

1. `LOOP.md`의 검증 명령을 **실제로 실행**한다 (전체, 부분 아님).
2. 통과로 보이면 `loop-verifier` 에이전트를 스폰해 rubric 전체를 독립 판정시킨다.
   자기 코드에 대한 자기 판정은 "주장"이지 "증명"이 아니다.
3. verifier의 FAIL은 곧 이 이터레이션의 FAIL이다.

### 5. Record — 디스크에 남겨라 (모델은 세션 사이에 전부 잊는다)

`.loop/memory.md` 갱신 — **Fail → Investigate → Verify → Distill** 순서:

- 실패: 실패 사실 + 원인 1줄을 Attempts에 기록. 같은 유형 실패 2회째면 일반 규칙로 승격해 Rules에 추가.
- 성공: rubric 체크(`LOOP.md`), Attempts에 1줄.
- **토큰 규율**: Attempts는 최근 10개만 유지(오래된 것 삭제 — 교훈은 이미 Rules로 승격됐어야 함). 각 항목 2줄 이내.

### 6. Continue / Stop 판정

- **계속**: 미달성 항목이 남았고 stop 조건 미해당 → 다음 이터레이션 (자동 모드면 /loop가 재호출).
- **중단 (사람에게 에스컬레이션)**: 다음 중 하나면 멈추고 상황을 보고한다:
  - 같은 rubric 항목에서 **연속 3회 실패** (접근 자체가 틀렸을 가능성)
  - `LOOP.md`의 max_iterations 도달
  - rubric 밖의 결정이 필요 (스코프 변경, 의존성 추가, 파괴적 작업)
- **완료**: 전 항목 ✅ → 검증 명령 전체를 마지막으로 1회 재실행 → **사람 리뷰 요약** 출력:
  변경 파일 목록, 각 rubric의 증거(명령+결과), verifier 판정, 사람이 직접 확인해야 할 부분.
  루프의 검증은 주장이다 — 최종 확인은 엔지니어의 몫임을 명시한다.

## 토큰 효율 규칙 (모든 모드 공통)

- 이터레이션 시작 시 읽는 것은 `LOOP.md` + `.loop/memory.md` + 해당 rubric 관련 파일**만**. 전체 탐색 금지.
- 보고는 간결하게: 이터레이션당 3~5문장 (한 일, 결과, 다음 항목).
- memory.md가 60줄을 넘으면 Distill(규칙 승격 + Attempts 정리)부터 한다.
